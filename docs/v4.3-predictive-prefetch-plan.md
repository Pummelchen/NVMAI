# NVMAI v4.3 bounded predictive expert prefetch plan

## Objective

Raise end-to-end decode throughput by at least 10% over a fresh v4.1 control
for Ornith 1.5 35B-A3B in both 4-bit and 8-bit formats, while retaining exact
routing/math, `F_NOCACHE` bounded I/O, and v4.1 hit/fixup as a fallback.

This is not a restart of v4.2's Metal-I/O, event, pool-layout, or GPU-residency
experiments.  The v4.3 hypothesis is narrower: future expert bytes may be read
early, but only exact router output can select, adopt, or execute them.

## Reviewed implementation tasks

1. **Baseline and trace-only instrumentation**
   - Preserve production `hit-fixup`, bounded `pread`, host synchronization,
     per-slot cache layout, and LFU.
   - Record actual route, cache residency before planning, exact misses, storage
     timing, and exposed I/O for every routed layer.
   - Gate: fresh v4.1 controls must be reproducible before any performance
     comparison is accepted.

2. **Predictor probe, no speculative reads**
   - Generate an adjacent-layer candidate route after the current router is
     available.  It is telemetry only: exact routing remains the only source
     of cache plans and expert execution.
   - Report raw top-k overlap separately from nonresident-miss recall,
     precision, candidate rank, and available lead time.
   - Gate: proceed only if useful nonresident-miss recall and lead time show
     enough potential to hide at least the required 5.5 ms/token (4-bit) and
     10.4 ms/token (8-bit) net savings.

3. **Bounded raw staging and priority I/O**
   - Add a fixed model-wide raw expert staging ring.  It is independent of
     authoritative cache slots, so a wrong prediction cannot evict or mark an
     exact expert `LOADING`.
   - Extend persistent bounded pread scheduling with P0 exact demand and P1
     speculation.  P0 work outranks queued P1 work; queued obsolete P1 work is
     dropped; exact demand joins matching in-flight P1 work instead of reading
     twice.
   - Gate: bounded mode remains `F_NOCACHE`; staging capacity and bytes are
     explicit and whole-machine memory stays within the declared budget plus
     the small staging allowance.

4. **Exact adoption**
   - When the exact next-layer router selects a ready staged expert, make the
     normal cache plan, copy only that expert into its reserved slot, publish
     it only after bytes are valid, and retain the existing generation/pin/lease
     lifetime rules.
   - Staged but unused data expires without touching the cache.  A failed or
     short speculative read is discarded and falls back to the normal P0 path.
   - Gate: barrier and hit/fixup output remain within existing golden tolerance
     across all-hit, mixed, and all-miss cache states.

5. **Measured policy selection**
   - Benchmark fixed top-M values 1, 3, and 5 first.  Higher ranks require a
     measured gain because speculative I/O can delay demand reads.
   - Assess cache-policy or unequal-layer-budget changes only after the
     prefetch path has a proven result.
   - Gate: promote only if both 4-bit and 8-bit clear +10% over fresh v4.1
     controls, maintain deterministic greedy output, do not regress p95 token
     latency, and retain bounded-memory behavior.

6. **Qualification and release evidence**
   - Use three fresh, interleaved A/B processes per quantization and the same
     prompt, seed, context, KV precision, cache budget, MTP state, and
     thinking mode.
   - Record token rate, p50/p95/p99, cache hit/miss rate, demand/speculative
     bytes, useful-prefetch precision/recall, total/hidden/exposed I/O,
     process RSS, memory pressure, and swap.
   - Document accepted and rejected variants; do not claim a production gain
     from a single run.

## Safety invariants

- Predictions never alter selected experts, router weights, accumulation order,
  quantization, or residual order.
- A speculative read never occupies, evicts, or publishes an authoritative
  cache slot until exact routing confirms it.
- Exact demand always outranks queued speculation.
- Slot generations and pins remain valid until both I/O and all GPU consumers
  retire.
- Event/Metal-I/O controls remain experimental and out of the v4.3 production
  path unless fresh profiling disproves this plan.

## Experiment result: 2026-08-21

Implemented as an opt-in experiment only:

```text
NVMAI_PREDICTIVE_PREFETCH=1
NVMAI_PREFETCH_TOP_M=4   # 1...8; default 4 when enabled
```

The implementation uses a four-entry raw `MTLBuffer` staging ring, direct
bounded `pread`, exact-route-only adoption, and demand-before-speculation
queueing. It does not modify authoritative cache mappings until the exact
router requests a completed staging entry. Greedy 4-bit output matched the
same run with the feature disabled byte-for-byte; the normal 4-bit golden
baseline also passed.

On the 128-token continuous-prose probe with 64 expert slots/layer, the
model-aware next-router probe had 64.1% actual nonresident-miss recall at
top-8 (56.4% precision), while the transition-only fallback had only 3.25%
recall. At top-4, the model-aware probe gave 32.6% recall and 79.7% precision.

The first end-to-end interleaved 4-bit/8-bit run did **not** meet promotion:

| Quant | Off median tok/s | Top-4 median tok/s | Change |
| --- | ---: | ---: | ---: |
| 4-bit | 7.934 | 7.621 | -3.9% |
| 8-bit | 5.050 | 5.443 | +7.8% |

The two individual pairs also varied materially with warm/thermal state. This
is not evidence of the required +10% for either quantization, so v4.1 remains
the production path and this feature remains disabled by default. The limiting
issue is lead time: a single next-layer prediction often begins too late, and
its reads can still consume SSD service while the following demand work starts.
The next eligible experiment is two-stage prediction (a smaller earlier set,
then refinement), measured with explicit prefetch completion timestamps and
demand-join telemetry; do not promote the current path without that evidence.
