# NVMAI v4.1 expert streaming engine

This document is the source-level assessment and validation contract for the
v4.1 decode scheduler. It supersedes the unimplemented hit/fixup proposal in
[`v4-core-design.md`](v4-core-design.md). The runtime is not being rewritten:
the required kernels, packed format, bounded cache, and async fetch boundary
already exist.

## Verified baseline

The decode dependency chain is:

```text
attention/router command
  -> CPU reads top-k expert IDs
  -> cache plan classifies hits and reserves misses
  -> shared expert GPU command
  -> asynchronous expert reads into fixed shared Metal buffers
  -> routed phase 1
  -> routed phase 2 reduction and residual
```

The existing implementation already has subset phase-1 kernels for both affine
and 4-bit experts, and commits the shared expert before the asynchronous fetch.
Prefill separately uses expert-major grouping and a bounded tile scheduler; v4.1
does not replace that path.

The old global barrier was caused by an implementation defect, not an
architectural limitation. `RealForwardRunner` copied the reusable hit and miss
arrays before populating them. Swift arrays have value semantics, so both local
snapshots stayed empty and the runtime always encoded the full phase 1 after I/O.

## v4.1 decode schedule

For a mixed-residency top-k set:

1. The cache planner reserves exact slot generations for every routed expert.
2. A lease pins those generations until the last consuming GPU command finishes.
3. The shared expert and resident routed phase 1 are committed immediately.
4. Misses load asynchronously into their already-reserved slots.
5. A fixup command computes phase 1 only for miss positions.
6. The common phase-2 reduction consumes all activation rows in original top-k
   order, then releases the lease after completion.

All-hit and all-miss layers keep the simpler full-phase path. The former performs
no storage read; the latter has no useful resident subset to schedule early.
`NVMAI_DECODE_EXPERT_EXECUTION=barrier` retains the prior schedule as an A/B and
correctness control. Production defaults to `hit-fixup`; unknown values fail
closed.

## Cache and memory invariants

Each model layer owns a fixed number of preallocated, 2 MiB-aligned shared Metal
buffers. Slot storage never grows with sequence length or miss count. Each slot
has explicit state and ownership:

```text
empty -> loading -> resident -> loading (new generation)
                         \-> pinned while referenced by GPU work
```

- Loading slots cannot be hits or eviction victims.
- Pinned slots may be shared by read-only GPU commands but cannot be evicted.
- Every reservation increments a generation; stale plans fail instead of using
  overwritten weights.
- Failed reads return their reserved slots to `empty`.
- The default reader uses persistent `F_NOCACHE` descriptors and preads directly
  into slot memory. No temporary full-model or full-layer weight buffer exists.

The `.gturbo` container already matches the access pattern. Routed experts live
in per-layer files; every logical expert is one 16 KiB-aligned contiguous blob at
`physicalRank * expertStride`, containing gate/up/down weights and their affine
metadata in compute-ready quantized form. No format rewrite or runtime repacking
is needed for hit/fixup execution.

## Instrumentation

`NVMAI_RUNNER_STATS=1` now reports per-request:

- cache hits, misses, hit rate, evictions, and reloads;
- bytes and read operations;
- bounded-histogram p50/p95/p99 batch-load latency;
- I/O hidden percentage and number of mixed hit/fixup layers;
- the existing attention, I/O-await, command-encoding, RDADVISE, and body times.

`NVMAI_KERNEL_STATS=1` separates resident phase-1 GPU time from miss-fixup plus
phase-2 time. The fixed histogram avoids an unbounded latency sample array.

## I/O backend decision

Metal I/O is available on the target M3 and supports concurrent file-to-buffer
loads. v4.1 includes an experimental `NVMAI_EXPERT_IO_BACKEND=metal` path and a
synthetic direct-load correctness test. It is not the production default because
the public Metal I/O contract does not promise `F_NOCACHE` behavior. It must beat
pread on decode throughput, exposed I/O, tail latency, CPU cost, and whole-machine
memory pressure before adoption. `pread` remains the only backend with the
required bounded page-cache behavior already established.

## Deliberate non-changes

- GPU-only residency classification is deferred. The current slot model uses
  separate `MTLBuffer` objects, so eliminating CPU binding would require a
  contiguous cache/address-table redesign. The repaired path already overlaps
  resident computation; profiling must show the remaining top-k readback and
  binding cost is material before that churn is justified.
- Cross-layer lookahead is not implemented because layer L+1 routing depends on
  layer L output. Same-layer previous-token prefetch predicts experts that are
  already resident and cannot recover true misses.
- Compression is not added to the critical path; expert payloads remain directly
  consumable by the existing quantized Metal kernels.

## Validation contract

Unit and synthetic validation must cover mixed partitioning, all-hit/all-miss
boundaries, subset/full numerical equality, slot pinning, generation stability,
failed-read cleanup, bounded statistics, Metal I/O range correctness, and existing
Qwen/Ornith runtime tests. Real-model acceptance additionally requires:

- barrier and hit/fixup responses match for fixed seeded requests;
- 4-bit and 8-bit Ornith golden output remains within the existing tolerance;
- no slot is overwritten before GPU completion under stress;
- resident memory stays within the configured cache/KV budget;
- hit/fixup improves exposed I/O or end-to-end decode without regressing prefill.

Run `benchmark/nvmai_hit_fixup_ab.py` only after the repository's model-process,
memory-pressure, release-build, and verified-install preconditions pass. The
script records commit, hardware, macOS, Swift, configuration, raw logs, responses,
and cold/repeat measurements under `.build/benchmark-results/`.
