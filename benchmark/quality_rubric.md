# Quality rubric — "difference of swift and c++ in detail"

Each answer is scored 0-100. The score is the % of what a strong
senior-engineer answer would contain.

## Dimensions
1. Correctness (40%) — factual accuracy about both languages. Penalize:
   wrong facts (Swift uses a GC; C++ has no exceptions; wrong ARC/RAII,
   memory-model, or type-system claims).
2. Coverage / depth (30%) — major axes addressed and how deeply: memory
   management, type system, generics/templates, performance & ABI, error
   handling, concurrency, safety, ecosystem/use cases, interop.
3. Structure & clarity (20%) — organized (sections/headings/tables),
   readable, answers "in detail" with substance, no rambling.
4. Examples / evidence (10%) — concrete code, tables, or comparisons
   illustrating the claims.

## Bands
- 90-100: comprehensive, accurate, structured, with illustrative code.
- 75-89: solid and correct across most axes, minor gaps or light examples.
- 60-74: correct on main points but shallow or missing key axes.
- 40-59: partial — some correct content, significant omissions or errors.
- <40: superficial, mostly wrong, or truncated/off-topic.

## Notes
- Score the model content, not the CLI wrapper (strip banners/footers).
- Truncation is not itself a penalty; incomplete answers may lose coverage.
- Reasoning-on answers: judge only the final answer text.
